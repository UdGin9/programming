На олимпиадах, в Яндекс Контесте, на Codeforces и других платформах решение проверяет не человек, а **тестирующая система**. Чтобы получать «OK», нужно понимать, как она работает.

## Как проходит проверка

1. Вы отправляете код программы.
2. Система запускает его на заранее подготовленных **тестах** – их могут быть десятки. Каждый тест – это входные данные и правильный ответ.
3. Программа получает входные данные так, как будто их ввели с клавиатуры (через `input()`), а всё, что она выводит через `print()`, сохраняется.
4. Вывод программы сравнивается с правильным ответом. Если хотя бы на одном тесте ответ не совпал или программа работала слишком долго – решение не принято.

**Запомни:** система не читает ваш код и не знает, что вы «имели в виду». Она сравнивает только вывод. Лишнее слово или другой регистр («Да» вместо «ДА») – и ответ неверный.

## Из чего состоит условие

Разберём типичное условие задачи:

> **Задача. Сумма двух чисел**
>
> Даны два целых числа $a$ и $b$. Выведите их сумму.
>
> **Формат входных данных:** в одной строке через пробел записаны два целых числа $a$ и $b$ ($-10^9 \le a, b \le 10^9$).
>
> **Формат выходных данных:** одно число – сумма $a$ и $b$.
>
> **Ограничение времени:** 1 секунда. **Ограничение памяти:** 256 МБ.
>
> **Пример.** Ввод: `2 3`. Вывод: `5`.

- **Условие** – что нужно сделать.
- **Формат входных данных** – как читать данные: сколько чисел и в одной строке они или в разных. От этого зависит, писать `int(input())` или `map(int, input().split())` (см. [Ввод с клавиатуры](<Ввод с клавиатуры.md>)).
- **Формат выходных данных** – что и в каком виде выводить. Выводить нужно ровно это и ничего больше.
- **Ограничения на данные** (например, $n \le 10^5$) – подсказка, насколько быстрым должно быть решение (см. [Сложность алгоритмов](<Сложность алгоритмов>)).
- **Ограничения времени и памяти** – сколько программе разрешено работать на одном тесте.
- **Примеры** – обязательный минимум для проверки. Но если программа проходит примеры, это ещё не значит, что она пройдёт все тесты.

Решение этой задачи:

```python
a, b = map(int, input().split())
print(a + b)
```

## Вердикты

После проверки система выдаёт **вердикт** – результат проверки. Обычно вместе с ним сообщается номер первого непройденного теста. Если решение упало на тесте 1, чаще всего это пример из условия.

| Вердикт | Расшифровка | Что значит | Что проверить |
| ------- | ----------- | ---------- | ------------- |
| OK, AC | Accepted | решение прошло все тесты | 🎉 |
| WA | Wrong Answer | неверный ответ на каком-то тесте | логику, крайние случаи, формат вывода |
| TLE | Time Limit Exceeded | программа работала дольше лимита | сложность алгоритма, бесконечный цикл |
| MLE | Memory Limit Exceeded | превышен лимит памяти | слишком большие списки |
| RE | Runtime Error | программа завершилась с ошибкой | `IndexError`, `ZeroDivisionError`, `ValueError` при чтении, `EOFError` (прочитано больше строк, чем есть) |
| CE | Compilation Error | код не удалось запустить | синтаксис, выбран правильный язык |
| PE | Presentation Error | неверный формат вывода (есть не во всех системах) | лишние слова, разделители |

## Частые ошибки

### 1. Текст в input()

```python
n = int(input("Введите число: "))   # ❌
n = int(input())                    # ✅
```

Подсказка «Введите число:» выводится туда же, куда и `print()`, и система считает её частью ответа. Результат – WA. В задачах с автопроверкой `input()` всегда пишется **без аргументов**.

### 2. Лишние слова в ответе

```python
print("Ответ:", a + b)   # ❌
print(a + b)             # ✅
```

Регистр тоже важен: если в условии написано «ДА», то «Да» и «да» – неверный ответ.

### 3. Неправильный способ чтения

- Числа записаны в одной строке, а вы читаете `int(input())` – программа попытается превратить в число всю строку `"2 3"` и упадёт с `ValueError`. Результат – RE.
- Числа записаны на разных строках, а вы читаете `a, b = map(int, input().split())` – будет прочитана только первая строка с одним числом, и программа упадёт с ошибкой `ValueError: not enough values to unpack`.

**Запомни:** перед тем как писать код, внимательно прочитайте формат входных данных.

### 4. Вещественные числа

Если в условии написано «выведите ответ с точностью до 3 знаков после запятой», используйте f-строку: `print(f"{x:.3f}")` (см. [Строки](<Строки>)).

Вещественные числа хранятся в компьютере неточно:

```python
print(0.1 + 0.2)          # 0.30000000000000004
print(0.1 + 0.2 == 0.3)   # False
```

Поэтому вещественные числа не сравнивают через `==`, а проверяют, что разница очень мала: `abs(a - b) < 1e-9`.

### 5. Не проверены крайние случаи

Тесты почти всегда проверяют «неудобные» входные данные: $n = 0$ или $n = 1$, все числа одинаковые, отрицательные числа, максимальные значения из ограничений.

Классическая ошибка – поиск максимума:

```python
a = list(map(int, input().split()))
mx = 0            # ❌ если все числа отрицательные, ответ будет 0
for x in a:
    if x > mx:
        mx = x
print(mx)
```

Правильно начинать с первого элемента: `mx = a[0]`. Или просто использовать `max(a)`.

### 6. Медленное решение

Решение может быть правильным, но не укладываться в ограничение по времени. Как заранее понять, успеет ли программа, – в теме [Сложность алгоритмов](<Сложность алгоритмов>).

## Как тестировать своё решение

1. Запустите программу на всех примерах из условия.
2. Придумайте свои маленькие тесты, ответ к которым можно посчитать вручную.
3. Проверьте крайние случаи (см. выше).
4. Оцените, уложится ли решение по времени при максимальных ограничениях.

> [!tip] Для любопытных: большой тест
> Чтобы проверить скорость, можно сгенерировать большой тест отдельной программой:
> ```python
> # gen.py
> import random
> n = 100000
> print(n)
> print(*[random.randint(1, 10**9) for _ in range(n)])
> ```
> И запустить решение на нём в терминале:
> ```no-highlight
> python gen.py > test.txt
> python solution.py < test.txt
> ```

## Быстрый ввод

Если во входных данных очень много строк (сотни тысяч), `input()` работает медленно. Его можно заменить на более быстрый вариант:

```python
import sys
input = sys.stdin.readline
```

После этого `input()` читает строку **вместе с символом перевода строки** `\n` в конце. Функция `int()` его игнорирует, а при чтении строк нужно убрать его вручную: `s = input().strip()`.

## Шаблон решения

Удобно сразу оформлять решение через функцию `main` (см. [Функции](<Функции>)):

```python
def main():
    n = int(input())
    a = list(map(int, input().split()))
    print(sum(a))


main()
```
