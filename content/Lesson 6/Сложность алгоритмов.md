Две программы могут решать одну задачу правильно, но одна отработает за сотую долю секунды, а другая – за несколько часов. Чтобы заранее понять, успеет ли решение уложиться в ограничение по времени, оценивают **сложность алгоритма**.

## Как измерять скорость

Время работы в секундах зависит от компьютера, поэтому его неудобно сравнивать. Вместо этого считают, **сколько операций** выполняет программа в зависимости от размера входных данных $n$.

```python
# сумма элементов списка: один проход – n операций
s = 0
for x in a:
    s += x
```

```python
# все пары элементов: для каждого из n элементов – ещё n, итого n · n операций
for i in range(n):
    for j in range(n):
        print(a[i], a[j])
```

## O-нотация

Точное число операций не важно – важно, **как оно растёт** при увеличении $n$. Для этого используют запись $O(\ldots)$ («О большое»): константы и младшие слагаемые отбрасываются.

- $3n + 5$ операций → $O(n)$
- $\frac{n^2}{2} + n$ операций → $O(n^2)$
- $100$ операций при любом $n$ → $O(1)$

Основные классы сложности и количество операций для разных $n$:

| Сложность | Название | Пример | $n = 10$ | $n = 1000$ | $n = 10^6$ |
| --------- | -------- | ------ | -------- | ---------- | ---------- |
| $O(1)$ | константная | `a[i]`, формула | 1 | 1 | 1 |
| $O(\log n)$ | логарифмическая | цифры числа, бинарный поиск | 3 | 10 | 20 |
| $O(\sqrt{n})$ | корень | проверка на простоту | 3 | 32 | 1000 |
| $O(n)$ | линейная | один проход по списку | 10 | 1000 | $10^6$ |
| $O(n \log n)$ | | сортировка | 33 | $10^4$ | $2 \cdot 10^7$ |
| $O(n^2)$ | квадратичная | два вложенных цикла | 100 | $10^6$ | $10^{12}$ |
| $O(2^n)$ | экспоненциальная | перебор всех подмножеств | 1024 | $\approx 10^{301}$ | – |

Разница огромная: при $n = 10^6$ алгоритм за $O(n)$ работает доли секунды, а алгоритм за $O(n^2)$ – больше суток.

## Успеет ли решение

Python выполняет **примерно $10^7$ простых операций в секунду**. Подставьте максимальное $n$ из условия в сложность своего алгоритма и сравните с этим числом.

Отсюда полезная таблица: по ограничениям в условии можно догадаться, какой алгоритм от вас ждут (для ограничения времени 1 секунда):

| Ограничение на $n$ | Допустимая сложность | Что это обычно значит |
| ------------------ | -------------------- | --------------------- |
| $n \le 10$ | $O(n!)$ | перебор всех перестановок |
| $n \le 20$ | $O(2^n)$ | перебор всех подмножеств |
| $n \le 200$ | $O(n^3)$ | три вложенных цикла |
| $n \le 3000$ | $O(n^2)$ | два вложенных цикла |
| $n \le 10^5$ | $O(n \log n)$ | сортировка, бинарный поиск |
| $n \le 10^6$ | $O(n)$ | один или несколько проходов |
| $n \le 10^{12}$ | $O(\sqrt{n})$ | перебор делителей до корня |
| $n \le 10^{18}$ | $O(\log n)$ или $O(1)$ | формула, деление пополам |

> [!note] Примечание
> Цифры примерные и даны для Python. Программы на C++ работают в 10–50 раз быстрее, поэтому там те же алгоритмы выдерживают большие $n$.

## Как оценить сложность кода

**1. Последовательные части – складываются, остаётся самая медленная.**

```python
for i in range(n):        # O(n)
    print(i)
for i in range(n):        # O(n)
    for j in range(n):    #   × O(n)
        print(i, j)
# итого O(n) + O(n²) = O(n²)
```

**2. Вложенные циклы – перемножаются.**

```python
for i in range(n):          # n раз
    for j in range(i + 1, n):   # в среднем n/2 раз
        ...
# n · n/2 → O(n²)
```

**3. Если на каждом шаге $n$ уменьшается в несколько раз – получается $O(\log n)$.**

```python
# количество цифр числа (задача из занятия 4)
count = 0
while n > 0:
    n //= 10
    count += 1
```

У числа $10^{18}$ всего 19 цифр – цикл выполнится 19 раз, хотя само число огромное.

## Скрытая сложность встроенных операций

Одна строчка кода – не всегда одна операция. Многие встроенные функции внутри сами проходят по всему списку:

| Операция | Сложность |
| -------- | --------- |
| `len(a)`, `a[i]`, `a[i] = x` | $O(1)$ |
| `a.append(x)`, `a.pop()` | $O(1)$ |
| `a.pop(0)`, `a.insert(0, x)` | $O(n)$ – все элементы сдвигаются |
| `x in a`, `a.count(x)`, `a.index(x)`, `a.remove(x)` | $O(n)$ |
| `min(a)`, `max(a)`, `sum(a)` | $O(n)$ |
| `a[l:r]` – срез | $O(r - l)$ – создаётся копия |
| `a.sort()`, `sorted(a)` | $O(n \log n)$ |

Поэтому такой короткий код на самом деле квадратичный:

```python
# сколько элементов встречается ровно один раз
cnt = 0
for x in a:               # n раз
    if a.count(x) == 1:   # count – ещё один проход по списку: n операций
        cnt += 1
# O(n²): при n = 10⁵ это 10¹⁰ операций – TLE
```

**Запомни:** вызов `count`, `in`, `index`, `remove`, `min`, `max`, `sum` или среза **внутри цикла** – повод задуматься о сложности.

## Пример 1. Проверка на простоту за $O(\sqrt{n})$

На прошлом занятии мы написали функцию `is_prime`, которая перебирает все делители от 2 до $n - 1$ (см. [Функции](<Функции>)). Её сложность – $O(n)$.

Заметим: если у числа $n$ есть делитель $d > \sqrt{n}$, то у него есть и парный делитель $\frac{n}{d} < \sqrt{n}$. Например, у $36$ делители $9$ и $4$, $12$ и $3$. Значит, достаточно проверить делители до $\sqrt{n}$:

```python
def is_prime(n):
    if n < 2:
        return False
    d = 2
    while d * d <= n:     # то же, что d <= √n, но без вещественных чисел
        if n % d == 0:
            return False
        d += 1
    return True
```

Для $n = 10^{12}$ старая версия сделала бы $10^{12}$ операций (больше суток), а новая – всего $10^6$ (доли секунды).

## Пример 2. Префиксные суммы

**Задача.** Дан список из $n$ чисел и $q$ запросов. Каждый запрос – два числа $l$ и $r$, нужно вывести сумму элементов с $l$-го по $r$-й. Ограничения: $n, q \le 10^5$.

**Простое решение** – для каждого запроса посчитать сумму заново:

```python
for _ in range(q):
    l, r = map(int, input().split())
    print(sum(a[l - 1:r]))     # O(n) на каждый запрос
```

Сложность $O(n \cdot q)$, то есть до $10^{10}$ операций – TLE.

**Быстрое решение.** Заранее посчитаем **префиксные суммы**: `pref[i]` – сумма первых $i$ элементов. Тогда сумма с $l$-го по $r$-й элемент – это сумма первых $r$ элементов минус сумма первых $l - 1$:

$$\text{sum}(l, r) = \text{pref}[r] - \text{pref}[l - 1]$$

| $i$ | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| `a[i - 1]` | – | 3 | 1 | 4 | 1 | 5 |
| `pref[i]` | 0 | 3 | 4 | 8 | 9 | 14 |

Сумма со 2-го по 4-й элемент: `pref[4] - pref[1]` = $9 - 3 = 6$ (и правда, $1 + 4 + 1 = 6$).

```python
n = int(input())
a = list(map(int, input().split()))

pref = [0] * (n + 1)
for i in range(n):
    pref[i + 1] = pref[i] + a[i]

q = int(input())
for _ in range(q):
    l, r = map(int, input().split())
    print(pref[r] - pref[l - 1])     # O(1) на каждый запрос
```

Сложность $O(n + q)$ – около $2 \cdot 10^5$ операций вместо $10^{10}$.

**Запомни:** если одно и то же вычисление повторяется много раз – посчитайте его заранее один раз и сохраните.

## Память

Память тоже ограничена, обычно 256 МБ. Список из $10^6$ чисел занимает несколько десятков мегабайт – это нормально. А таблица $10^4 \times 10^4$ – это $10^8$ элементов, и она в память уже не поместится.

## Шпаргалка

| Код | Сложность |
| --- | --------- |
| формула, `a[i]`, `append` | $O(1)$ |
| деление `n` пополам или на 10 в цикле | $O(\log n)$ |
| `while d * d <= n` | $O(\sqrt{n})$ |
| один цикл по списку, `sum`, `max`, `in`, `count` | $O(n)$ |
| `sort`, `sorted` | $O(n \log n)$ |
| два вложенных цикла, `count` или `in` внутри цикла | $O(n^2)$ |

**Чтобы проверить, успеет ли решение:** подставьте максимальное $n$ в сложность. Получилось меньше $10^7$ – успеет.
